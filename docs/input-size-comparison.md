# 열화상 검출 입력 크기 비교

## 판단

현 단계에서는 160x160을 기본 후보로 유지한다. 각 크기에 맞춰 추가 학습했을 때 256은 신뢰도 0.75에서 정밀도를 유지하며 전체 재현율이 2.16%p 높아졌지만, PC CPU 추론 시간이 약 2.45배였다. 320은 전체 재현율이 4.75%p 높아진 대신 정밀도가 낮아졌고 추론 시간은 약 3.44배였다. 성능이 같다는 뜻은 아니며, 이번 결과에서는 연산량 증가 대비 개선 폭이 제한적이라는 판단이다.

사람이 없는 영상의 오검출과 인원수 평균 오차는 큰 입력에서 줄었다. 따라서 256을 무의미한 후보로 버리지는 않는다. 현장 영상에서 이 차이가 반복되는지와 라즈베리파이의 시간 여유를 확인한 뒤 비교할 대안으로 남긴다. 모델이나 설정을 장비에 배포하지는 않았다.

## 비교 조건

2026-09-10, [LSI 추가 학습 실험](model-training.md)의 자료와 가중치로 입력 크기를 비교했다. 운영 프로그램, 카메라 표시 설정, 기본 추론 주기 3 FPS는 변경하지 않았다.

- 모든 크기는 본문에서 너비x높이로 표기한다. ONNX와 `benchmark_lsi.py --shapes`만 높이x너비 순서다.
- 원본 LSI 영상은 164x129이며, 같은 8비트 변환 영상과 같은 박스 주석을 사용한다. 실제 Lepton의 160x120 영상은 아니다.
- 검증 영상 888장으로 신뢰도 기준을 선정하고, 기존 시험 영상 8,136장으로 비교한다. 시험 자료에는 사람 박스 4,169개와 사람이 없는 영상 4,857장이 포함된다.
- 종횡비를 유지하는 레터박스를 사용한다. 160x128은 160 크기에서 `--rect`로 패딩을 줄인 결과다. 영상을 정사각형으로 늘리거나 주석 박스를 새로 만들지 않는다.
- 모델은 기존과 같은 YOLOv5l 구조다. LSI는 경량 모델 이름이 아니라 추가 학습에 사용한 데이터셋이다.
- 정확도 평가는 PyTorch FP32, 배치 32, NMS IoU 0.45, 정답 매칭 IoU 0.5다. 사람 높이별 재현율은 리사이즈 전 원본 픽셀 기준이다.
- 고정 신뢰도 0.25와 0.75를 모두 기록한다. 별도로 각 입력의 검증 자료에서 정밀도 95% 이상을 만족하는 기준 중 재현율이 가장 높은 값을 0.25~0.95, 0.05 간격으로 선택한다. 시험 결과로 기준을 선택하지 않는다.

입력 크기만 바꾸는 실험과 해당 크기로 다시 학습하는 실험을 구분한다. 학습과 추론 크기를 맞추라는 [YOLOv5 공식 안내](https://github.com/ultralytics/yolov5/wiki/Tips-for-Best-Training-Results#training-settings)를 참고했다. 단순 확대 실험의 결과만으로 큰 입력의 가능성을 배제하지 않는다.

## 동일 가중치에서 입력만 변경

160x160으로 학습한 후보의 동일 가중치를 사용했다. 아래는 신뢰도 0.75를 고정한 시험 결과다.

| 입력 | AP50 | 정밀도 | 전체 재현율 | 20~39픽셀 재현율 | 오검출 박스 | 사람 없는 영상의 오검출 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 160x160 | 91.81% | 96.15% | 82.73% | 72.49% | 138 | 19 / 4,857 |
| 160x128 | 91.45% | 98.90% | 73.61% | 61.15% | 34 | 2 / 4,857 |
| 256x256 | 89.79% | 92.41% | 77.38% | 70.22% | 265 | 12 / 4,857 |
| 320x320 | 81.24% | 83.49% | 69.75% | 57.60% | 575 | 10 / 4,857 |

AP50은 신뢰도 기준 전반의 지표이며 0.75에서만 계산한 수치가 아니다. 오검출 박스는 사람이 있는 영상의 중복 검출이나 정답과 충분히 겹치지 않는 박스도 포함한다. 마지막 열은 사람이 없는 영상에서 하나라도 박스가 나온 횟수로, 여러 박스가 나와도 한 장으로 센다. 연속 프레임의 같은 오검출이 반복될 수 있으므로 서로 독립된 오검출 사건 수는 아니다.

검증 자료에서 별도로 고른 기준은 160x160이 0.75, 160x128이 0.80, 256x256이 0.90이었다. 이때 시험 재현율은 각각 82.73%, 67.55%, 34.64%였다. 320x320은 탐색한 기준 중 검증 정밀도 95% 목표를 만족하는 값이 없었다. 검증 구간과 시험 구간의 분포가 달라 정밀도 보정이 재현율을 과하게 낮출 수 있다는 점도 확인됐다.

160x128은 AP50 차이는 작지만 같은 신뢰도에서 재현율 차이가 크다. 따라서 패딩 감소를 무조건적인 무손실 최적화로 취급하지 않는다. 해당 입력에 맞춘 학습과 신뢰도 재검증은 별도 과제다.

## 학습과 추론 크기를 맞춘 비교

모두 같은 LLVIP 원본 가중치에서 시작했다. 학습 자료, 검증 구간, 시드 42, SGD, 배치 32, 최대 20회, 조기 종료 대기 5회와 하이퍼파라미터 파일을 유지하고 입력 크기만 인자로 바꿨다. YOLOv5의 크기별 자동 앵커 점검과 손실 정규화는 기본 학습 절차를 따른다. 각 학습의 최적 가중치는 시험 자료가 아니라 검증 지표로 선택했다.

| 학습 및 추론 입력 | 학습 종료 | 선택한 학습 회차 | AP50 | AP50-95 |
| --- | ---: | ---: | ---: | ---: |
| 160x160 | 13회 | 8회, epoch 7 | 91.81% | 65.48% |
| 256x256 | 19회 | 14회, epoch 13 | 92.50% | 70.81% |
| 320x320 | 10회 | 5회, epoch 4 | 92.61% | 70.92% |

다음은 신뢰도 0.75를 고정한 결과다.

| 입력 | 정밀도 | 전체 재현율 | 20~39픽셀 재현율 | 오검출 박스 | 미탐 박스 | 사람 없는 영상의 오검출 | 인원수 평균 절대 오차 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 160x160 | 96.15% | 82.73% | 72.49% | 138 | 720 | 19 / 4,857, 0.39% | 0.1013명 |
| 256x256 | 96.17% | 84.89% | 75.43% | 141 | 630 | 5 / 4,857, 0.10% | 0.0921명 |
| 320x320 | 94.80% | 87.48% | 78.68% | 200 | 522 | 1 / 4,857, 0.02% | 0.0858명 |

인원수 평균 절대 오차는 각 영상에서 `|검출 박스 수 - 정답 사람 수|`를 구해 전체 영상에 평균한 값이다. 박스 위치가 잘못되어도 인원수는 맞을 수 있으므로 박스 정밀도와 함께 해석한다. 사람이 없는 영상이 전체의 약 60%인 자료의 평균이며, 실제 군중 장면에서 같은 수준의 오차를 보장하지 않는다.

높이 10~19픽셀인 정답 140개는 신뢰도 0.75에서 세 모델 모두 0개를 검출했다. 큰 입력으로 추가 학습해도 이번 실험에서는 해당 문제가 개선되지 않았다. 이 구간의 학습 사례 부족과 검증 사례 부재는 여전히 남는다.

낮은 신뢰도에서의 결과도 함께 기록한다. 0.25에서는 다음과 같았으며, 입력 크기에 따라 신뢰도 분포가 달라지므로 단일 기준만으로 일반적인 우열을 단정하지 않는다.

| 입력 | 정밀도 | 전체 재현율 | 오검출 박스 | 10~19픽셀 검출 |
| --- | ---: | ---: | ---: | ---: |
| 160x160 | 66.65% | 91.80% | 1,915 | 21 / 140 |
| 256x256 | 85.59% | 89.88% | 631 | 0 / 140 |
| 320x320 | 78.41% | 90.67% | 1,041 | 3 / 140 |

검증 정밀도 95% 목표로 별도 보정한 기준은 160과 256이 0.75, 320이 0.70이었다. 320의 0.70 시험 결과는 정밀도 91.45%, 재현율 88.49%, 오검출 345개였다. 검증 자료에서 목표를 만족해도 다른 구간에서 같은 정밀도가 보장되지는 않았다. 비교 도구는 목표에 도달하지 못한 경우 임계값을 임의로 정하지 않고 보정 결과를 비워 둔다.

## CPU 추론 시간

AMD Ryzen 5 9600X, Windows, ONNX Runtime 1.20.1 CPU 실행기, FP32, 배치 1, 연산 내부 스레드 4개에서 측정했다. GPU 학습과 평가가 종료된 뒤 실행했다. 라즈베리파이 실측이나 프로그램 전체 처리 시간은 아니다.

먼저 같은 160 학습 가중치를 입력별로 변환해 비교했다.

| 입력 | 160 대비 입력 면적 | 중앙값 | 95백분위 | 160 대비 추론 시간 |
| --- | ---: | ---: | ---: | ---: |
| 160x128 | 0.80배 | 12.76ms | 13.11ms | 0.84배 |
| 160x160 | 1.00배 | 15.28ms | 15.97ms | 1.00배 |
| 256x256 | 2.56배 | 36.30ms | 38.20ms | 2.38배 |
| 320x320 | 4.00배 | 52.37ms | 53.86ms | 3.43배 |

추가 학습한 가중치도 각각 변환해 같은 방식으로 재측정했다. 256 학습 모델은 중앙값 37.48ms, 95백분위 38.38ms였고, 320 학습 모델은 중앙값 52.62ms, 95백분위 53.85ms였다. 160 기준 대비 각각 2.45배와 3.44배다. 입력 면적 비율은 연산량의 참고 지표이지 실제 지연 시간이나 전력 소모 비율과 같지 않다.

160x128의 시간 감소는 약 16%였지만 정확도 유지가 확인되지 않았고, 현재 운영 검출기는 정사각형 입력만 받는다. 직사각형 평가용 ONNX를 운영 프로그램에 바로 넣는 방식은 지원하지 않는다.

## 재현 도구

기존 [학습 환경](model-training.md#학습-환경)에서 저장소 루트를 기준으로 실행한다. 출력 경로가 이미 존재하면 새 경로를 지정한다. 원본 데이터, 가중치, ONNX와 상세 예측은 Git 추적 대상이 아닌 경로에만 저장한다.

```powershell
python training/evaluate_lsi.py --weights outputs/lsi-training/candidate/weights/best.pt --input-size 320 --split val --output outputs/lsi-input-comparison/candidate-val-320
python training/evaluate_lsi.py --weights outputs/lsi-training/candidate/weights/best.pt --input-size 320 --split test --output outputs/lsi-input-comparison/candidate-test-320
python training/compare_lsi.py --pair train160-input320 outputs/lsi-input-comparison/candidate-val-320 outputs/lsi-input-comparison/candidate-test-320 --output outputs/lsi-input-comparison/comparison-320.json
python training/train_lsi.py --input-size 320 --output outputs/lsi-input-comparison/trained-320
python training/benchmark_lsi.py --weights outputs/lsi-training/candidate/weights/best.pt --output outputs/lsi-input-comparison/cpu --shapes 128x160 160x160 256x256 320x320
```

160x128 평가는 `--input-size 160 --rect`로 실행한다. 추가 학습 결과 평가는 `--weights`를 해당 `weights/best.pt`로 바꾸고 학습 크기에 맞는 `--input-size`를 지정한다. `compare_lsi.py --pair`를 반복해 여러 평가를 하나의 JSON으로 비교할 수 있다.

256 추가 학습과 평가도 위 명령의 크기 및 출력 이름을 256으로 바꿔 재현한다. 추가 학습 가중치의 CPU 측정은 다음과 같다.

```powershell
python training/benchmark_lsi.py --weights outputs/lsi-input-comparison/trained-256/weights/best.pt --output outputs/lsi-input-comparison/cpu-trained-256 --shapes 256x256
python training/benchmark_lsi.py --weights outputs/lsi-input-comparison/trained-320/weights/best.pt --output outputs/lsi-input-comparison/cpu-trained-320 --shapes 320x320
```

CPU 벤치마크는 공식 YOLOv5 변환 함수로 입력별 정적 ONNX를 만들고, 크기별 검증 영상 5장에서 PyTorch와의 수치 일치를 확인한다. 단일 프레임 추론만 측정하며 전처리, NMS, 카메라 수신과 화면 출력은 제외한다. 조건별 10회 예열 후 30회 측정을 3라운드 반복하고, 순서를 바꾸어 중앙값과 95백분위 지연 시간을 기록한다. [ONNX Runtime 공식 스레드 설정](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)에 따라 연산 내부 스레드를 4개로 고정한다.

## 해석상의 제한

- 학습 시드 42의 단일 학습 결과다. 작은 차이를 통계적으로 동등하거나 유의한 차이라고 단정하지 않는다.
- 기존 시험 자료를 반복 분석한 탐색 실험이다. 독립된 새로운 시험이나 현장 평가로 보지 않는다.
- 높이 10~19픽셀은 시험 박스 140개이며 검증 구간에는 없다. 이 구간의 기준을 별도로 검증하거나 최적화하지 못했다.
- LSI 촬영 환경과 Lepton의 온도 기반 전처리가 다르다. 야외, 뜨거운 지면, 조리기구나 가까운 실내 사람에 대한 결과를 보장하지 않는다.
- 정확도는 공식 YOLOv5 평가 로더에서 측정했다. 실제 프로그램의 리사이즈 및 표시 필터까지 포함한 동일 영상 재생 평가도 별도로 필요하다.
- PC CPU 시간은 라즈베리파이 지연 시간이나 전력 측정이 아니다. 실물에서 3 FPS와 전력, 발열을 확인하기 전에는 운영 입력 크기를 바꾸지 않는다.
