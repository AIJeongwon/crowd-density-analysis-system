# 개선 예정 사항

현재 기준선은 Raspberry Pi가 Lepton 3.5와 SLAMTEC RPLIDAR C1 데이터를 로컬에서 결합해 인원 수를 추론하고, 서버에는 `people_count`와 `confidence`만 전송하는 엣지 추론 구조다. 서버는 위치별 면적과 수용 인원으로 밀도·점유율·혼잡도를 계산한다.

## 1. 영속 저장소

현재 백엔드는 메모리 저장소를 사용하므로 재시작하면 결과가 사라진다.

- 초기 운영: SQLite
- 다중 서버 또는 분석 단계: PostgreSQL
- 저장 대상: 추론 결과, 위치 설정, heartbeat와 장애 이력
- 보존 기간과 개인정보 최소화 정책

## 2. 모델 정확도와 버전 관리

모델은 Python `ModelAdapter` 플러그인으로 분리되어 있다.

- ONNX/TFLite/PyTorch별 검증된 어댑터
- 모델 버전, 체크섬과 전처리 버전
- `people_count` 정답 데이터셋과 오차 지표
- 단일 센서 모델과 융합 모델 비교
- 낮은 신뢰도 표시 정책

## 3. 센서 중합 정책 고도화

현재 Fusion은 설정 주기마다 두 FIFO 큐에 데이터가 모두 있으면 하나씩 결합하고, 기본 10번째 확인마다 두 큐를 비우고 해당 결합을 건너뛴다.

- 타임스탬프를 이용한 근접 프레임 매칭
- 허용 가능한 최대 시각 차이
- 큐 폐기 횟수와 지연 시간 계측
- 센서별 수집 속도 차이와 backpressure
- 결합 누락률 모니터링

## 4. 장비와 통신 상태

클라이언트는 `GET /health`와 연속 실패 한도를 사용한다. 운영 단계에서는 다음을 추가한다.

- 노드별 마지막 heartbeat와 추론 수신 시각
- 각 작업 스레드의 장애 횟수
- 요청 지연 분포와 warning 횟수
- 원격 재시작 및 버전 확인
- CPU, 장치 온도와 디스크 공간

## 5. 혼잡도 계산 개선

현재 서버는 `people_count / capacity`를 백분율 점수로 바꾸고 35/70을 기준으로 단계를 구분한다.

- 위치별 임계값
- 시간대별 이동 평균과 급격한 변화 감지
- 출입 흐름과 체류 인원 구분
- 사용자 피드백 기반 위치 설정 보정
- 동일 위치의 여러 노드 결합

## 6. API와 보안

- 노드별 API key 또는 상호 TLS
- HTTPS
- 요청 크기 및 rate limit
- 제한된 CORS origin
- OpenAPI와 API versioning
- 표준 오류 응답과 관측 가능성

## 7. 엣지 데이터 보호

원시 열화상과 LiDAR 데이터는 기본적으로 Raspberry Pi 밖으로 전송하지 않는다.

- `/tmp/cdas` 용량과 자동 삭제 주기
- 운영 환경의 디버그 모드 제한
- 파일 접근 권한과 암호화
- 장애 분석용 데이터 반출 절차
